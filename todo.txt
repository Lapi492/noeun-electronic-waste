Figma Make -> Vercel 마이그레이션 작업 지침
(백엔드 없는 프론트엔드 전용 프로젝트)

이 파일에 적힌 순서대로 하나씩 진행해줘. 각 단계 끝나면 결과를 간단히 요약해줘.

===============================
0단계. 프로젝트 구조 파악
===============================
- 프로젝트 전체 구조를 훑어봐줘.
- package.json, tsconfig.json, vite.config.ts (또는 next.config.js),
  tailwind.config.js 등 핵심 설정 파일이 다 있는지 확인해줘.
- 빠진 파일이 있으면 목록으로 알려줘.

===============================
1단계. 빌드 가능 상태로 복구
===============================
- 누락되었거나 비어있는 설정 파일(package.json, tsconfig.json,
  tailwind.config.js, vite.config.ts 등)을 채워줘.
- npm install 실행해서 의존성 에러(버전 충돌 등) 있으면 해결해줘.
- npm run build 실행해서 성공하는지 확인해줘. 실패하면 원인 찾아서 고쳐줘.
- 이 단계가 완료되기 전까지는 다음 단계로 넘어가지 마.

===============================
2단계. Figma 전용 코드 제거
===============================
- "figma:" 로 시작하는 특수 import 경로가 있는지 찾아서
  표준 로컬 이미지 import 방식으로 바꿔줘.
- Figma Make가 자동으로 삽입한 불필요한 스크립트, 주석, 메타데이터를 정리해줘.
- figma_app.min.js 등 Figma Make 전용 스크립트/라이브러리 참조가 남아있으면 제거해줘.

===============================
3단계. 에셋 재점검
===============================
- 이미지, 폰트, favicon 파일들이 실제로 public/ 또는 assets/ 폴더에
  존재하는지 확인해줘.
- 코드에서 참조는 되어 있는데 실제 파일이 없는 깨진 링크를 찾아서 알려주고 고쳐줘.

===============================
4단계. 스타일 검증
===============================
- Tailwind 설정(커스텀 색상, 폰트, breakpoint 등)이 원본과 일치하는지 확인해줘.
- npm run dev로 로컬 실행 후 화면을 확인해줘.
- (원본 Figma 배포 사이트 URL: https://funky-verse-50263597.figma.site )
  위 URL과 비교해서 레이아웃/스타일 차이가 있는지 점검해줘.

===============================
5단계. Vercel 배포 최적화
===============================
- SPA 라우팅이 필요한 경우 vercel.json에 rewrite 규칙을 추가해줘.
- 환경변수가 있다면 .env.example 파일로 정리해줘.
- favicon, 메타 태그, OG 이미지 등 기본 SEO 요소가 있는지 점검해줘.

===============================
6단계. Git 준비
===============================
- git 저장소로 초기화해줘.
- .gitignore 파일을 만들어서 node_modules, .env, dist/build 폴더 등을
  제외 처리해줘.
- (GitHub push 및 Vercel 연동은 사용자가 직접 진행함 - Claude Code는
  여기까지만 준비해주면 됨)

===============================
우선순위 요약
===============================
1) 빌드 성공 (1단계) - 가장 중요, 안 되면 이후 단계 의미 없음
2) Figma 전용 코드 제거 (2단계)
3) 에셋/스타일 검증 (3, 4단계)
4) 배포 설정 (5, 6단계)
